태스크 $ARGUMENTS 의 구현 계획만 세워줘. 파일은 수정하지 마.

## 읽을 것 (여기서 시작)
1. docs/03_impl/tasks.md 의 $ARGUMENTS 행 — 태스크 · 완료 조건 · 선행 태스크
2. 그 행에 적힌 architecture.md 절. 절 번호가 없으면 대상 클래스의 3절(3.2~3.7)
3. architecture.md 추적표 · 4절에서 완료 조건의 테스트 이름이나 $ARGUMENTS 가 나오는 행
4. 위에서 언급된 ADR
5. 이번에 고칠 기존 Source/AIGame 파일
근거를 달 수 없는 결정이 생기면 CLAUDE.md '작업 방식'의 근거 규칙대로 찾는다. 어느 절이 왜 필요한지 먼저 말하고 읽는다.

## 계획 전에 확인
- 선행 태스크의 코드가 실제로 있는가 (없으면 멈추고 보고)
- 3절 헤더 선언 · 기존 코드 · CLAUDE.md 사이의 충돌 (있으면 계획 전에 보고)

## 계획 형식
1. 완료 조건 (tasks.md 그대로)
2. 읽은 자료: architecture.md 절 번호 · ADR 번호 · 기존 파일
3. 수정 · 생성할 파일
4. 새 클래스 · 함수 · 변수: 3절 헤더 선언에 있는 것과 없는 것을 나눠 적고, 항목마다 근거 절을 단다. 3절에 없는 것은 추가 이유(단순성 원칙의 성능/정확성)
5. 처음 쓰는 엔진 API와 선언 헤더 경로 (3.9에 있으면 그 줄을 인용, 없으면 엔진 소스에서 찾은 경로, 못 찾으면 '확인 필요')
6. 추가할 Build.cs 의존 모듈
7. 작성할 테스트: 이름(설계 문서 그대로)과 확인하는 규칙 한 줄씩
8. 실행 순서: 테스트 작성 → 구현 → 에디터 종료 확인 → Build.bat → RunTests.bat <필터> → 실패하면 원인을 고치고 재실행(테스트 · 기대값은 고치지 않는다) 
9. 사람이 에디터에서 할 작업
10. 설계에 답이 없어 정해야 하는 것 — 추측하지 말고 질문으로
