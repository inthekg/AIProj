## 0. 이 문서 쓰는 법
- Claude Code는 이 문서를 읽고 **5장의 태스크를 순서대로** 진행한다. 태스크 하나가 끝나면 멈추고, 사용자 승인을 받은 뒤 다음 태스크로 간다.
- 진행 상황은 5장 요약표의 '상태' 칸에 적는다.
- 태스크 ID는 A00 형식이다. T01 형식은 docs/03_impl/tasks.md의 구현 태스크를 가리킨다.
- 태스크를 마친 기록과 1장 이후의 아트 결정(D15~)은 docs/ai-log/art_log.md에 적는다. docs/ai-log/log.md에는 적지 않는다.
- 1장 결정표에서 '내 판정'이 빈칸인 항목은 대화에서 명시적으로 답하지 않은 항목이다. '선택 이유'는 모두 사용자가 직접 쓴다.

## 3. 공통 규격

### 3.1 해상도 · 크기
- UMG 설계 기준 1080×1920(세로). DPI Scaling은 UE 기본값(Shortest Side, 1080 = 1.0)을 유지하고 확인만 한다.
- 출력 크기 = 기준 화면에서 보이는 크기 그대로(1배). 더 큰 크기가 필요하면 SVG에서 다시 출력한다.
- 모든 크기는 4의 배수.
- 배경 1080×2400: 긴 화면(20:9)까지 덮도록 위아래 여유를 둔다. 중요한 그림은 가운데 1080×1920 안. UMG에서는 Scale Box(Scale To Fill)로 가운데 맞춤.
- 같은 묶음은 같은 캔버스
  - 재료 · 조합 · 떡 · 완성 모찌 · 모자이크: 320×320. 단독 재료는 가운데에 크게 그리고, 진열 겹침 위치는 위젯이 맞춘다(ADR-0010 보완, art-style.md 3.6)
  - 손님 5명: 같은 캔버스, 발 위치와 머리 높이 통일
- 축소는 2배 이내. UI 텍스처는 밉맵이 없어서 2배 넘게 줄이면 가장자리가 거칠어진다. 더 작게 쓰는 곳은 소형 사본을 따로 출력한다.
- 터치 영역(재료통 · 찜기 · 버리기 · 버튼): Android 권장 최소 48dp. 1080 폭 기기에서 대략 144px(기기마다 다름).
- 앱 아이콘: 핵심 그림은 가운데 약 2/3 안. 적응형 아이콘은 108dp 캔버스 중 가운데 72dp가 보인다. UE 5.5 에디터에는 적응형 아이콘 칸이 없어 일반 아이콘 5칸(36 · 48 · 72 · 96)만 쓴다(`AndroidTargetSettingsCustomization.cpp`, art_log.md D61).
- 런치 화면: UE는 런치 이미지를 res/drawable(mdpi)에 넣고 기기에서 dp 크기 그대로 가운데에 그린다(늘리지 않음, 남는 곳은 검정 — 엔진 `Build/Android/Java/res/drawable/splashscreen_p.xml`). 그래서 1080×1920이 아니라 432×960으로 출력해 화면을 덮고 넘치는 가장자리는 잘리게 하며, 중요한 그림은 가운데 360×640 안에 둔다(art_log.md D62).

### 3.2 파일
- PNG, sRGB, 투명 배경(배경 2장 · 런치 화면 · 앱 아이콘은 불투명)
- 이미지 안에 글자 없음(D10)
- 이름: `T_<분류>_<이름>` (2장 표 그대로)
- 레포 폴더
  - `Art/Source/<분류>/*.svg` — 원본
  - `Art/Export/<분류>/*.png` — 출력(커밋)
  - `Art/Export/_sheets/` — 검수용 모아 보기
  - `Scripts/art/` — 변환 스크립트. `node_modules`는 .gitignore
- UE 폴더: `Content/UI/Textures/<분류>/`

### 3.3 UE 5.5 임포트 설정 (전부 동일)
- Texture Group: UI / Mip Gen Settings: NoMipmaps / Compression Settings: UserInterface2D (RGBA) / sRGB: 켬
  - UserInterface2D는 비압축이고 밉맵이 없어서 2의 거듭제곱 크기가 아니어도 된다. 모바일에서 텍스처가 하얗게 나오는 "See Power of Two Settings" 문제도 이 설정으로 피한다.
- 여러 장은 Property Matrix로 한 번에 바꾼다(에셋 여러 개 선택 → 우클릭 → Asset Actions → Bulk Edit via Property Matrix).
- 9-slice(패널 · 버튼 · 게이지): 이미지 브러시 Draw As = Box, Margin(0~1 비율). 권장 값은 A08에서 art-style.md에 적는다.
- 메모리: 비압축이라 1080×2400 배경 1장이 약 10MB. 로비 · 영업은 레벨이 달라 한 번에 1장만 올라가므로 허용. 실기기에서 문제가 되면 배경만 기본 압축으로 바꾸는 것을 검토한다(확인 필요).
- 앱 아이콘: Project Settings > Platforms > Android > Icons — Icon · MDPI Icon: T_AppIcon_48, LDPI Icon: T_AppIcon_36, HDPI Icon: T_AppIcon_72, XHDPI Icon: T_AppIcon_96
- 런치 화면: Project Settings > Platforms > Android > Launch Images — Show launch image 켬, Launch Portrait: T_Launch

## 4. 컨셉 유지 규칙
구체 수치는 docs/02_design/art-style.md 3장(A03 확정, art_log.md D24 · D27).
- 분위기: 부드럽고 편안하고 따뜻한 파스텔 플랫 그림, 아주 단순한 캐릭터 그림체
- 생성 지시와 문서에 특정 게임 이름을 쓰지 않는다. 특징으로만 쓴다(굵은 외곽선, 적은 색 수, 평평한 색).
- 팔레트 13색 파스텔(hex 코드). 배경 · 런치 화면만 전용 2색(`.beige` 가게 벽 · `.sky` 하늘, art_log.md D58 · D59)을 더 쓴다
- 외곽선: 부드러운 갈색(순검정 금지), 굵기는 캔버스 크기 등급별
- 명암: 물체 안쪽 명암 · 하이라이트 없음(평평한 색). 혼자 놓이는 물체의 바닥 그림자만
- 모서리는 둥글게. 얼굴은 점 눈 + 작은 입(볼터치 · 코 · 귀 없음), 큰 둥근 머리
- 금지: 복잡한 그라데이션, 질감, 사진 같은 표현
- 공용 스타일 파일 하나(`Art/Source/_style.css`: 팔레트 · 선 굵기 · 그림자 색)를 변환할 때 모든 SVG에 넣는다. 한 곳을 고치면 전체에 반영된다.
- 기준 에셋(A03: 딸기 · 딸기 통 · 팥 통 · 완성 모찌 · 손님 01)을 승인받은 뒤 생산하고, 묶음마다 모아 보기 1장으로 나란히 놓고 검수한다.

### A00. Node.js 설치 (사람)
- Node.js는 PC에서 JavaScript를 실행하는 프로그램이다. 함께 설치되는 npm(패키지 관리자)으로 SVG → PNG 변환 라이브러리(sharp)를 받는다.
- 설치: nodejs.org에서 LTS 버전 Windows 설치 파일을 받아 기본 옵션으로 설치. 또는 PowerShell에서 `winget install OpenJS.NodeJS.LTS`
- 완료 조건: 새 터미널에서 `node -v`와 `npm -v`가 버전을 출력한다. 설치 후 Claude Code를 다시 시작한다(PATH 반영).

### A01. 변환 파이프라인 (AI)
- 만들 것
  - `Scripts/art/`: package.json, 변환 스크립트 1개
  - `Art/Source/_style.css`: 공용 스타일(임시 값)
  - `.gitignore`에 `Scripts/art/node_modules/` 한 줄
- 동작
  - `Art/Source/**/*.svg` → `Art/Export/**/*.png`. 출력 크기는 각 SVG의 width / height.
  - 변환할 때 `_style.css`를 각 SVG에 넣어 렌더한다.
  - 소형 사본이 필요한 파일만 스크립트 안의 짧은 목록으로 추가 출력한다.
  - 모아 보기: 지정한 폴더의 PNG를 한 장(폭 약 1092px)에 이름 · 크기와 함께 배치해 `Art/Export/_sheets/`에 저장한다.
- 기능은 '변환'과 '모아 보기' 두 가지만 둔다. 옵션 · 함수를 늘리지 않는다.
- 라이브러리: sharp. 설치나 SVG 변환이 실패하면 @resvg/resvg-js로 바꾸고 이유를 보고한다.
- 완료 조건
  - 테스트 SVG 1장 → 지정 크기 PNG, 투명 배경(모서리 알파 0)
  - `_style.css`의 색을 바꾸면 출력에 반영됨
  - 모아 보기 1장 생성
  - 테스트 파일은 확인 후 지운다
- 결과를 보고하고 멈춘다.

### A02. 디자인 테스트 ①: 화면 배치 초안 (AI + 사람)
- 입력(사람): 영업 화면 손그림 1장 또는 현재 UMG 화면 캡처(있으면). 없으면 GDD '화면 구성'만으로 진행한다.
- 만들 것: `Art/Source/_layout/Layout_Business.svg`, `Layout_Lobby.svg` (1080×1920, 회색 상자로 배치)
  - 영업: 상단 바 · 손님 줄(슬롯 5) · 제작 메모 · 진열대 · 재료통 · 작업대 + 찜기(+ 버리기)
  - 로비: 일차 · 골드 · 다음 해금 카드 · 찜기 업그레이드 카드 · 영업 시작

- 완료 조건: 사용자가 배치와 크기를 승인한다.

### A03. 디자인 테스트 ②: 스타일 가이드 + 기준 에셋 3장 (AI + 사람)

### A04. 재료 7장 + 재료통 7장 (AI)

### A05. 작업대 상태 (AI)

## 6. Claude Code 작업 규칙
- 파일 쓰기 범위: `Art/`, `Scripts/art/`, `docs/02_design/art-style.md`, `docs/ai-log/art_log.md`, 이 문서의 '상태' 칸, `.gitignore` 한 줄. `Content/` · `Source/` · `Config/`는 수정하지 않는다(UE 임포트는 사람이 한다).
- SVG를 고칠 때는 바뀐 부분만 고친다. 파일 전체를 다시 쓰지 않는다.
- 검수용 이미지는 모아 보기 1장으로 본다. Claude가 이미지를 볼 때 드는 비용은 ⌈가로/28⌉ × ⌈세로/28⌉ 토큰이다(512px 16장을 따로 보면 약 5,776, 1092px 1장이면 약 1,521).
- 태스크가 끝나면 멈추고 보고한다: 만든 파일, 모아 보기 경로, 사용자가 정해야 할 것. art_log.md 작업 기록에 한 줄 초안을 넣는다(판정 · 근거 칸은 비우고, 커밋 칸은 세션 정보만).
- 샘플 · 변형안은 사용자가 요청할 때만 만든다.
- 확인하지 못한 것은 '확인 필요'로 표시하고 추측으로 채우지 않는다.
- 텍스트 파일은 UTF-8(BOM 없음) — ADR-0002
- 판단 이유 · 회고 문장은 쓰지 않는다(사용자가 쓴다).
