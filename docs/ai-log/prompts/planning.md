## 요약 — 잡아낸 비싼 추측과 해결 방식

| 항목 | 틀렸다면 생겼을 일 | 해결 |
|---|---|---|
| 채점 척도 미정 (0/1인지 단계형인지) | 0/1이면 동점 다수, 1~5면 최저점 11점이라 컷이 아무것도 거르지 못함 | 사용자 답: 0~3점 |
| 구현 가능성이 가점 항목 | 20시간을 넘는 후보도 나머지 만점이면 컷 통과 | 사용자 답: 게이트(필수 조건)로 전환 |
| 일정·Must 시간 관계 모호 | "4일"이 40시간 예산으로 읽힐 수 있음 | 사용자 답: 일정 재배분 (1~2일차 20시간 = Must) |
| 지침의 1단계 완료 기준 누락 | 통과 후보가 GDD 단계에서 재탈락 | 사용자 판정: 필수 조건으로 추가 |
| 만점 계산 불일치 (25점 지정, 실제 계산 24점) | 컷 15점의 의미가 달라져 통과 후보가 바뀜 | 2차 질문 → 6번을 시간복잡도 항목으로 대체, 만점 24 |
| 컷 경계 (15점 통과/탈락) | 경계 후보 판정이 갈림 | 2차 질문 → 16점 이상 통과 |

```
1. Must 기능 합계가 20시간안에 구현 가능한가? (3)
2. 데이터 주도 설계·저장·상태 관리 같은 C++ 시스템 설계를 보여줄 수 있는가(3)

5. 데이터·밸런스·테스트를 AI가 텍스트(CSV·C++)로 다룰 수 있는가 (1)
6. 자료구조, 알고리즘, 디자인패턴 등 이론 지식을 사용하여 더 나은 성능을 뽑아낼 여지가 있는가. (2)

[결과물] 가능한 컨셉 후보 최소 5가지를 점수순 오름차순으로 프롬프트에 제시. 
각 컨셉마다 점수, 간단한 게임 로직과, 기술포인트, AI 활용 가능 작업, 구현시 주의사항 및 위험성 을 명시한다. 
[기타] 결정이 필요하건 모르는 사항은 질문하기
```

## 점검 의견 (Claude 채팅) 과 판정

점검 결론: 채점 규칙에 구멍 두 개(척도 미정, 구현 불가 후보도 컷 통과)와 지침 대비 빠진 조건이 있어, 이대로면 채점 결과를 선정 근거로 쓰기 어려움.

## 확인 질문과 답

### 1차 (점검 직후)

| 질문 | 사용자 답 (원문) |
|---|---|
| ① 채점 척도 (0/1 · 0·1·2 · 기타) | 채점 척도 : 0~3 으로 잡고, 추가된 질문 점수 합하여 만점 총 25. 컷은 15 |
| ② Must 시간 상한 (v0 20h vs 지침 15h) | 시간 배분 다시함. 3번 참고하기. |
| ③ 구현 가능성: 게이트 vs 가점 | 게이트로 바꾸기 |

### 2차 (v1 작성 중 발견한 불일치)

| 질문 | 사용자 답 |
|---|---|
| 1번을 게이트로 빼면 2~6번(0~3점 × 가중치)만으로 만점 24점이라 25점이 성립하지 않음. 시간복잡도 항목과 6번의 관계는? | 6번 대체, 가중치 2 (만점 24) |
| 정확히 15점인 후보는 통과인가 탈락인가? | 16점 이상 통과 |

## v1 (최종)

```
[목표]
단기 게임 프로젝트의 컨셉 후보를 제시하고, 아래 필수 조건과 평가표로 1차 채점한다.

[목적]
AI 활용 능력을 강조하기 위한 신입 UE5 클라이언트 개발자 포트폴리오용 게임이다.
평가 관점은 재미가 아니라 완결성(시작→플레이→저장→재접속), AI 활용, 프로그래머 기술이다.
결과는 concept-selection.md의 후보·채점 원본으로 쓴다.

[컨텍스트]
- 엔진·플랫폼: UE 5.5, C++, Android, 세로 화면
- 인원: 1인
- 개발자 경험: DX11 자체 엔진, UE4 일부 경험, 모바일은 처음
- 작업 분담: 구현은 Claude Code가 한다. BP/UMG(.uasset) 작업은 사람이 에디터에서 직접 한다.

[일정] 4일 × 하루 10시간
- 1~2일차(20시간): Must 기능 구현
- 3일차: 나머지 작업
- 4일차: 성능 분석, 테스트, 배포

[후보 구성]
- 키우기형 1개와 간단 시뮬레이션 1개를 반드시 후보에 포함한다. 이 두 후보도 같은 기준으로 판정·채점하고, 탈락하면 탈락 목록에 넣는다.
- 통과 후보가 3개 이상 나오도록 후보를 충분히 만든다.

[필수 조건] 하나라도 어기면 채점하지 않고 탈락
1. Must 기능 5개 이하, 예상 시간 합계 20시간 이내 (Claude Code 구현 시간과 사람의 BP/UMG·에디터 작업 시간을 모두 포함)
2. 화면 4개 이하
3. 모바일 특화 요소 1개 이상 (예: 터치 제스처, 앱 백그라운드/복귀 처리, 세로 해상도 대응)
4. 기술 포인트 3개 이상, 각 기술 포인트가 특정 Must 기능에 연결됨

[평가표] 점수 = Σ(항목 점수 × 가중치), 만점 24점, 16점 이상 통과(15점 이하 탈락)
A. 데이터 주도 설계·저장·상태 관리 같은 C++ 시스템 설계를 보여줄 수 있는가 — 0~3점 × 3
B. 터치·세로 화면·짧은 세션·앱 전환이 자연스러운가 — 0~3점 × 1
C. 간단한 AI 이미지 생성만으로 게임이 성립하는가 — 0~3점 × 1
D. 데이터·밸런스·테스트를 AI가 텍스트(CSV·C++)로 다룰 수 있는가 — 0~3점 × 1
E. 시간복잡도 개선 — 0점 또는 3점 × 2
   - 이 컨셉의 Must 기능에서 실제로 일어나는 연산을 골라, 적용할 기법 이름(자료구조·알고리즘·디자인패턴)과 개선 전 → 후 시간복잡도를 적는다. n이 무엇이고 대략 몇 개 규모인지도 함께 적는다.
   - 오브젝트 풀, 싱글톤은 개선안으로 인정하지 않는다.
   - 개선 후 시간복잡도가 개선 전보다 효율적이면 3점, 개선안이 없거나 시간복잡도가 같으면 0점.

[결과물]
1. 통과 후보 — 총점 내림차순. 컨셉마다:
   - 총점, 항목별 점수(A~E)와 항목마다 한 줄 근거
   - 간단한 게임 로직
   - Must 기능 목록과 기능별 예상 시간·합계
   - 기술 포인트 (연결된 Must 기능 표시)
   - AI 활용 가능 작업
   - 구현 시 주의사항 및 위험성
2. 탈락 후보 — 한 줄씩: 이름 · 점수(필수 조건으로 탈락했다면 어긴 조건 번호) · 탈락 이유
3. 최종 선택·추천은 하지 않는다.

[행동 규칙]
```

- Claude가 보탠 것 (사용자 확인 필요):
  - 필수 조건 1번 괄호 — 예상 시간에 사람의 BP/UMG 작업 시간 포함
