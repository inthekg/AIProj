# AIGame — 게임 기획서 (GDD) · 초안 v0

> 2026-11-18 · Claude 채팅 초안. 범위 컷(MoSCoW)·수치·최종 결정은 사람이 확정한다.

## 개요
- 장르: 가게 운영 시뮬레이션 (하루 3분 단위 영업)
- 플랫폼: Android (세로)
- 가제: 모찌 한 알
- 한 줄 소개: 팥 앙금 위에 과일을 하나씩 해금해 가며, 3분짜리 하루 영업으로 과일모찌 가게를 키운다.

## 핵심 루프
- 영업 루프 (초 단위): 주문 말풍선 확인 → 빈 작업대 탭 → 메뉴(과일) 선택 → 제작 타이머 완료 → 기다리는 손님에게 자동 판매 → 골드
- 성장 루프 (일 단위): 영업 → 결산 → 과일 해금·작업대 추가 → 더 비싼 메뉴, 더 많은 손님 처리

```mermaid
flowchart LR
    Lobby[로비: 과일 해금 · 작업대 추가] --> Open[영업 약 3분]
    Open --> Result[결산: 매출 · 놓친 손님 · 폐기]
    Result -->|저장| Lobby
```

## 조작
- 탭만 쓴다. 한 손 조작 기준으로 작업대·메뉴 바는 엄지가 닿는 화면 하단에 둔다.
- 영업: 빈 작업대 탭 → 메뉴 바에서 과일 탭 → 제작 시작
- 로비: 해금·업그레이드 버튼, 영업 시작 버튼

## 게임 규칙 · 진행
- 시작 조건: 1일차, 골드 0, 팥모찌만 해금, 작업대 2칸
- 메뉴: 모든 모찌는 찹쌀피 + 팥 앙금이 기본이다. 과일은 0개(팥모찌) 또는 1개. 메뉴 목록 = 해금된 과일 목록
- 손님: 일차별 도착 간격으로 등장해, 해금된 메뉴 중 수요 가중치에 따라 하나를 주문한다. 인내심이 다하면 떠난다(매출 없음).
- 판매: 제작이 끝나면 그 메뉴를 기다리는 손님 중 먼저 온 손님에게 자동 판매한다. 기다리는 손님이 없으면 진열대 재고가 되고, 이후 그 메뉴를 주문한 손님은 재고에서 바로 구매한다.
- 당일 생산·당일 판매: 영업이 끝날 때 남은 재고는 폐기하고 결산에 표시한다.
- 승리 / 실패 조건: 하루 단위 실패는 없다. 목표는 모든 과일 해금.
- 진행: 일차가 오를수록 손님 도착이 빨라진다(Days.csv). 결산 골드로 과일을 해금하고 작업대를 늘린다.

## 화면 구성 (UI)
1. 로비(상점): 일차·골드, 과일 해금 목록, 작업대 추가, 영업 시작
2. 영업: 남은 시간·매출 / 손님 대기열(주문 말풍선 + 인내심 게이지, 최대 5칸) / 작업대 슬롯 + 메뉴 바 / 진열대 재고
3. 결산(팝업): 매출, 판매·놓친 손님·폐기 수, 다음 날로
- 일시정지 오버레이: 앱 복귀 시 "계속하기" (영업 화면 위에 표시)

## 기획 수치
수치는 Data/*.csv로 관리하고 DataTable로 불러온다. 여기에는 표 목록과 각 표의 용도만 적는다.

| 파일 | 용도 | 주요 컬럼 |
|---|---|---|
| Data/Fruits.csv | 메뉴(과일) 정의와 해금 조건. 한 줄 = 메뉴 하나 | FruitId, Name, UnlockCost, UnlockDay, Price, MakeTime, DemandWeight, Icon |
| Data/Days.csv | 일차별 영업 난이도 | Day, Duration, ArrivalMin, ArrivalMax, Patience, MaxQueue |
| Data/Upgrades.csv | 작업대 추가 비용 | Level, SlotCount, Cost |

- 과일 후보: 딸기, 귤, 블루베리, 키위, 청포도, 샤인머스캣. 몇 개를 넣을지는 설계 단계에서 확정한다.

## 저장
- 저장할 데이터: SaveVersion, Day, Gold, 해금한 FruitId 목록, 작업대 레벨
- 저장 시점: 결산 확정 직후, 로비에서 구매 직후, 로비 상태에서 앱이 백그라운드로 갈 때
- 영업 중 진행은 저장하지 않는다. 백그라운드로 가면 일시정지하고, 강제 종료되면 그날 영업을 처음부터 다시 한다.

## 범위 (5일)
- Must: M1~M5
- Should: 평판(놓친 손님 수 → 다음 날 도착률), 제작 속도 업그레이드, 효과음
- Could: 완성 시 모찌 단면 연출, 제작 3단계 탭(찰떡 반죽 → 앙금으로 과일 감싸기 → 찰떡으로 감싸기), 모든 과일 해금 축하 화면
- Won't: 앙금 종류 선택(팥 고정), 오프라인 수익, 손님 캐릭터 이동·애니메이션, 로컬 푸시 알림, 광고·결제·서버

## 기술 포인트
1. 이벤트 기반 영업 시뮬레이션 (M1, M2): 손님 인내심과 제작 완료를 만료 시각 기준 최소 힙으로 관리하고, Timer 하나로 다음 이벤트만 예약한다(Tick 없음). 매 프레임 전체 검사 O(n) → 다음 이벤트 확인 O(1), 넣고 빼기 O(log n).
2. 데이터 주도 해금 (M3): Fruits.csv에 한 줄을 추가하면 코드 수정 없이 메뉴가 늘어난다. 밸런스 변경 이력이 git diff로 남는다.
3. 영업 상태 머신과 앱 생명주기 (M1, M4): 로비 → 영업 → 일시정지 → 결산 상태 전이, 백그라운드 진입 시 일시정지·저장, 세이브 버전 관리.

## 리스크
1. 범위 팽창: 운영 시뮬레이션은 손님 연출과 제작 미니게임으로 쉽게 커진다. → 손님은 주문 말풍선만, 제작은 탭 한 번 + 타이머로 고정하고 나머지는 Could / Won't로 둔다.
2. M1(5h) 초과: 일정 전체가 밀린다. → 손님 1명·메뉴 1개로 루프를 먼저 PIE에서 돌린 뒤 확장한다.
3. 밸런스 붕괴: 너무 쉽거나 해금이 불가능해진다. → 시드를 고정한 시뮬레이션 스크립트로 일차별 매출 곡선을 11/20 전에 확인한다.
