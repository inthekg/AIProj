필수 조건 — 하나라도 어기면 채점 없이 탈락

## 선택: 과일모찌 가게 운영 "모찌 메이커" (골목 빵집 운영 변형)

### 경위
1. 1차 채점에서 골목 빵집 운영(간단 시뮬레이션)이 22점으로 통과(공동 3위)
2. 사용자가 빵집 컨셉을 과일모찌 가게로 변형 제안: 기본은 팥모찌, 과일을 해금해 나가는 구조
3. Claude 점검: 시스템 구조는 빵집과 같아 기간 내 가능(조건: 제작 단순화, 손님은 말풍선, 영업 중 저장 제외) → GDD 초안 작성(GDD_draft.md)
4. 사용자 추가 설계: 베이스 3종 + 과일 4종 순차 해금, 재료비, "아무거나" 주문, 찜기 게이지, 3클릭 수동 조립과 쓰레기 판정, 입력 상태, 영업 화면 레이아웃, MoSCoW
5. Claude 점검: 충돌 6건 정리, 질문 3건 → 사용자 결정: 골드 부족 시 최소 자금 보장 / Must는 단순 연출, 세부 모션은 Could / 찜기 업그레이드 추가
6. 사용자 수정: 혼합 모찌 판매가 배수(잠정 1.25), 버리기 버튼 → GDD v1.1

### 최종 컨셉 채점 (같은 기준, Claude 1차)

필수 조건: Must 5개·20h ✅ · 화면 3개 + 일시정지 오버레이 ✅ · 모바일: 한 손 탭 조작, 백그라운드 진입 시 일시정지·저장 ✅ · 기술 포인트 4개 모두 Must 연결 ✅

| 항목 | 점수 | 근거 |

| B | 2 | 영업 중 계속 조작하는 능동 플레이라 앱 전환은 일시정지로 처리 (빵집과 같음) |

| D | 3 | 재료·일차·찜기·밸런스 CSV, 시드 고정 시뮬레이션으로 밸런스 검증 가능 |

| 총점 | 23 | 통과 |

### 선택 이유
조건을 만족하는 후보 중 '골목 빵집 운영'을 게임으로서의 가치가 있도록, 차별점 있고 더 흥미로운 컨셉(트랜드인 과일모찌)으로 수정했다.

- 다른 통과 후보들은 조건은 만족하지만 차별점이 없거나 콘텐츠가 부족했다.
- 처음부터 재미까지 조건에 넣었다면 본래 프로젝트 목표에 맞지 않는 후보가 나올 가능성이 높을 거라고 판단함. 그래서 먼저 조건에 맞는 후보를 받은 뒤, 그중에서 더 나은 방안을 직접 고민했다.
- AI가 만든 기본 로직과 기능에 살을 붙이고, 게임 전체 흐름을 직접 따라가 보며 빈틈(연출 중 입력 무시, 버리기 기능 등)을 메워 최종 기획을 완성했다.
